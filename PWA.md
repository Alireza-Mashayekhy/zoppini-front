# Zoppini PWA

The storefront is a Persian, RTL Next.js App Router application. The install experience uses its existing Estedad font, neutral palette, square corners and actual Zoppini artwork. The 192/512/180px icons and maskable icon were derived from `public/opening/zoppini-logo-full.png`; the existing favicon remains unchanged.

## Operation and deployment

- `app/manifest.ts` exposes `/manifest.webmanifest`: `/` start URL, ID and scope, standalone display, any orientation, and `#f9f9f9` theme/background. Apple metadata and touch icon are in `app/layout.tsx`.
- `components/pwa/use-pwa-install.ts` registers `/sw.js` in production, captures `beforeinstallprompt`, watches `appinstalled` and standalone display mode, and supplies the modal. `lib/pwa/platform.ts` identifies manual guides; availability of the native CTA is based on the event, not UA. `lib/pwa/config.ts` controls the delay and cooldown. The first eligible visit waits for the load event and six seconds; the modal waits until other dialogs and the cookie banner are closed and does not interrupt transactional routes.
- Dismissal and the native `appinstalled` signal are saved only if preference storage is allowed by the site's consent manager. Without that consent, suppression lasts only for the current page load (including client-side navigation); a reload can show the offer again. Consent withdrawal removes these keys. Storage failures are tolerated.
- The service worker caches only the offline page and PWA icons; navigations are network-first, with an offline fallback only for non-sensitive paths. Other requests, including Next data, cart, checkout, auth, account, privacy and APIs, pass through untouched. No HTML, inventory, price, account or transaction responses are stored. The worker activates immediately and claims clients without forcing a reload. Registration checks for updates without the HTTP cache; `/sw.js` is served with `no-cache, no-store`. When changing the offline page or any precached icon, increment `CACHE` in `public/sw.js` so the new worker replaces the old assets. Do not add dynamic or personalized URLs to `ASSETS`.
- Deploy the manifest, worker and icons on the same HTTPS origin as the storefront, at the root paths. Ensure the reverse proxy doesn't rewrite or cache `/sw.js` and serves these files without authentication. The offline fallback is not presented on transactional routes, where browser/network errors are intentionally left untouched.

## Browser limitations and verification

`beforeinstallprompt` is Chromium-specific and browser-controlled; it may not fire due to eligibility, user settings, or existing installation. No nonfunctional button is shown in that case. iOS uses a manual share-menu guide (third-party browser support varies with iOS/browser version). Safari on macOS requires Sonoma or newer for Add to Dock; the guide is shown for Safari 17+ and explains the OS requirement. There is no universally reliable API to detect an app installed manually from another browser or to detect later uninstallation; standalone mode is detected, and native install events are remembered when consent permits. iOS installed apps and the browser can have separate storage.

Run `npx tsx --test tests/pwa.test.ts`, `npx tsc --noEmit`, and `npm run build` from `front`. For release, test on actual iPhone Safari/Chrome, iPad, Android Chrome, Windows Chrome/Edge, macOS Chrome/Edge/Safari (Sonoma+): exercise native prompt acceptance/dismissal, manual installation, standalone launch, Escape/outside/focus behavior, persistence with and without preference consent, transactional routes, offline public navigation, and a worker version update. Run Lighthouse and verify no console/network errors against the production HTTPS deployment and a working backend. Automated UA and worker mocks do not replace these device tests.
